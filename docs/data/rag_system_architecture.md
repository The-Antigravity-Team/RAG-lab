# RAG 시스템 아키텍처 및 최적화 가이드

## 1. RAG의 기본 개념
RAG(Retrieval-Augmented Generation)는 대규모 언어 모델(LLM)에 외부 지식을 실시간으로 연결하는 기술입니다. LLM의 고유한 단점인 환각(Hallucination) 현상을 방지하고, 특정 도메인의 사내 비공개 문서나 최신 데이터를 기반으로 신뢰도 높은 답변을 생성할 수 있습니다.

## 2. 청킹 전략 (Chunking Strategies)
문서를 작은 텍스트 조각(청크)으로 분할하는 것은 검색 품질에 직접적인 영향을 미칩니다.
- **적정 크기**: 일반적으로 500자에서 1000자 내외가 권장됩니다.
- **중복도 (Overlap)**: 청크 간 10~20%의 텍스트를 중복되게 설정하여, 문맥의 단절을 방지합니다.
- **분할기 선택**: 일반적인 텍스트 및 보고서는 문단 단위와 줄바꿈을 계층적으로 고려하는 `RecursiveCharacterTextSplitter`를 권장합니다.

## 3. 벡터 데이터베이스와 ChromaDB
벡터 데이터베이스는 고차원 임베딩 벡터를 저장하고 ANN(Approximate Nearest Neighbor) 알고리즘을 통해 수 밀리초 만에 가장 유사한 벡터를 찾아냅니다. ChromaDB는 SQLite 기반의 파일 시스템 영구 저장소를 지원하여 설치가 간편하고 로컬 개발 환경에 최적화되어 있습니다.

## 4. 검색 품질 향상을 위한 고급 기법
1. **하이브리드 검색 (Hybrid Search)**: 고유명사와 품번 검색에 강한 BM25 키워드 검색과 의미적 유사도를 찾는 Dense 벡터 검색을 결합합니다.
2. **리랭커 (Cross-Encoder Re-ranker)**: 1차 검색된 상위 10~20개의 문서 조각 중 질문과의 실제 연관도를 정밀 재평가하여 최상위 3개를 선별합니다.
