# 02. 텍스트 벡터화(Text Vectorization)와 임베딩(Embedding) 원리

## 1. 텍스트 벡터화란?
컴퓨터는 글자의 의미를 직접 계산할 수 없습니다. 따라서 자연어 문장을 **수학적 연산(거리, 각도, 유사도)이 가능한 숫자들의 배열(고차원 실수 벡터)**로 변환하는 작업을 **텍스트 임베딩(Text Embedding)** 또는 벡터화라고 부릅니다.

---

## 2. 임베딩 모델의 동작 메커니즘

1. **토큰화 (Tokenization)**: 문장을 의미 단위인 토큰(Token, 형태소/단어 조각)으로 분해합니다.
2. **신경망 인코딩 (Transformer Encoder)**:
   - 입력된 토큰들이 문장 내 다른 모든 토큰들과의 관계(Self-Attention)를 계산합니다.
   - 예: "배를 먹었다(과일)"와 "배를 탔다(선박)"에서 '배'의 벡터 표현이 문맥에 따라 다르게 계산됩니다.
3. **풀링 및 정규화 (Pooling & Normalization)**:
   - 각 토큰 벡터들을 평균(Mean Pooling)하여 문장 전체를 대표하는 단 하나의 고정 크기 벡터($D$차원, 보통 384, 768, 1024, 1536 등)로 압축합니다.
   - 벡터의 크기를 1로 맞추는 L2 정규화를 거칩니다 ($\|\mathbf{V}\| = 1$).

---

## 3. 벡터 유사도 측정 공식

벡터 공간에서 두 문서(또는 질문과 문서)가 얼마나 의미적으로 가까운지는 **각도(Angle)**를 통해 측정합니다.

### ① 코사인 유사도 (Cosine Similarity)
가장 널리 쓰이는 유사도 척도로, 벡터의 절대적 길이와 무관하게 **두 벡터가 가리키는 방향의 일치도**를 측정합니다.

$$\text{Cosine Similarity} = \cos(\theta) = \frac{\mathbf{A} \cdot \mathbf{B}}{\|\mathbf{A}\| \|\mathbf{B}\|} = \frac{\sum_{i=1}^{n} A_i B_i}{\sqrt{\sum_{i=1}^{n} A_i^2} \sqrt{\sum_{i=1}^{n} B_i^2}}$$

- **$1.0$**: 완전히 같은 방향 (의미가 매우 유사)
- **$0.0$**: 서로 직교 (어떠한 의미적 상관관계도 없음)
- **$-1.0$**: 정반대 방향

> **Tip**: 벡터들이 사전에 L2 정규화(길이가 1)되어 있다면, 분모가 $1 \times 1 = 1$이 되므로 **내적(Dot Product, $\mathbf{A} \cdot \mathbf{B}$)** 연산만으로 초고속 계산이 가능합니다.

### ② 유클리드 거리 (Euclidean Distance / L2 Distance)
두 점 사이의 직선 거리를 측정합니다. 거리가 0에 가까울수록 유사합니다.
$$d(\mathbf{A}, \mathbf{B}) = \sqrt{\sum_{i=1}^{n} (A_i - B_i)^2}$$

## 4. 실전 주의점: 언어별 임베딩 모델의 차이

임베딩 모델은 학습 데이터에 따라 언어 이해도가 천차만별입니다.

| 구분 | 영문 전용 모델 (예: all-MiniLM-L6-v2) | 다국어/한국어 지원 모델 (예: BGE-M3, nomic-embed-text) |
| :--- | :--- | :--- |
| **토크나이저** | 영어 중심 WordPiece / BPE | 다국어 토크나이저 (한국어 형태소 보존) |
| **한국어 이해도**| 한국어를 알 수 없는 바이트 단위로 쪼개어 유사도 왜곡 발생 | 한국어 어휘의 의미적 관계를 정확히 벡터 공간에 매핑 |
| **실무 적용** | 영문 전용 문서에 적합 | **한국어/혼합 기술 문서 RAG 구축 시 필수** |
