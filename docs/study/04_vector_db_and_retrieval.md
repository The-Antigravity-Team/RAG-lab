# 04. 벡터 데이터베이스(Vector DB)와 검색(Retrieval) 원리

## 1. 벡터 데이터베이스(Vector Store)란?
고차원 실수 벡터(Dense Vector)와 그에 대응하는 원본 텍스트 및 메타데이터를 저장하고, **주어진 쿼리 벡터와 가장 유사한 $K$개의 벡터를 수 밀리초(ms) 단위로 고속 검색**할 수 있도록 특화된 저장소입니다.

---

## 2. 왜 일반 DB(RDBMS) 대신 Vector DB를 쓰는가?

- **RDBMS / B-Tree 인덱스**: $A = B$ 같은 정확한 값 매칭이나 $A > B$ 같은 1차원 숫자 범위 비교에 특화되어 있어, 384차원 이상의 고차원 거리 연산 시 전체 행을 전수 조사(Full Table Scan)해야 하므로 극도로 느려집니다.
- **Vector DB / ANN (Approximate Nearest Neighbor)**:
  - HNSW (Hierarchical Navigable Small World), IVF (Inverted File Index) 같은 그래프 기반 탐색 알고리즘을 사용하여 수백만 개의 문서 중에서도 10ms 이내에 가장 가까운 이웃 벡터들을 찾아냅니다.

---

## 3. 대표적인 로컬 벡터 DB: ChromaDB

ChromaDB는 오픈소스 AI 파이프라인에서 가장 널리 쓰이는 벡터 저장소 중 하나입니다.
- **장점**:
  1. 가볍고 별도의 서버 프로세스나 데몬 없이 파이썬 로컬 디렉토리(`./chroma_db`)에 SQLite 기반으로 데이터를 영구 저장(Persistent Client)할 수 있습니다.
  2. 메타데이터 필터링(`source == "manual.pdf"`)과 벡터 유사도 검색을 동시에 지원합니다.
  3. 기본 내장 임베딩 함수를 제공하여 설치 즉시 실행 가능합니다.

---

## 4. 검색 단계의 핵심 개념들

### ① Top-K 검색
- 질문과 가장 유사한 상위 $K$개의 문서 청크만 선택하는 설정입니다.
- $K=3 \sim 5$가 일반적입니다. 너무 작으면 필요한 정보가 누락되고, 너무 크면 LLM 프롬프트에 불필요한 노이즈가 들어가 환각이 유발될 수 있습니다.

### ② 메타데이터(Metadata) 부착과 필터링
- 청크마다 `{ "source": "guide.pdf", "page": 3, "created_at": "2026-10-10" }` 같은 부가 정보를 함께 저장합니다.
- 답변 시 "어느 파일 몇 페이지에서 가져왔는지" 출처 인용(Citation)을 제공할 수 있습니다.

### ③ 검색 고도화 기법 (Advanced Retrieval)
1. **하이브리드 검색 (Hybrid Search)**:
   - 고유명사나 특정 키워드(예: 모델명 `Gemma-2-9b-it`)는 전통적인 키워드 검색(BM25)으로 잡고, 추상적인 맥락은 벡터 유사도로 잡아 둘을 합산하는 방식.
2. **리랭킹 (Re-ranking)**:
   - 1차로 벡터 DB에서 10~20개를 빠르게 뽑아낸 뒤, Cross-Encoder 모델로 질문과의 세밀한 연관도를 재채점하여 최상위 3개만 LLM에 전달하는 방식.
